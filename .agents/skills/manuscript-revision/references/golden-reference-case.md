# HybridQDL Golden Reference Case

Use HybridQDL as a process and acceptance reference, never as reusable
scientific prose. A successful project must produce the same classes of clean
deliverables for any reviewer and comment count:

1. an unchanged source manuscript;
2. a professionally revised highlighted manuscript;
3. a clean manuscript with identical approved text and no system highlights;
4. a response letter with one verbatim, traceable entry per comment;
5. a step-by-step Excel registry of plans, approvals, exact drafts, applied
   changes, locations, colors, QA, and responses; and
6. machine-readable approval, version, change, and verification records.

The defining control is researcher approval before application. For every
comment, present its exact text, proposed response, and all linked changes
together. Permit response editing and granular draft selection. Only after all
packages have explicit decisions may deterministic DOCX mutation run. Any
change to the source, comment, or complete approved draft invalidates approval.

Acceptance is based on invariants and output quality, not matching HybridQDL
wording, file names, reviewer count, or topic.
